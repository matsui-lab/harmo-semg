# 記録に適用できる意味情報の昇格

## 判定の意味

`source_verified` は、供給された明示的な定義を、データセット版・記録・ヘッダーハッシュ・チャンネル・属性の範囲で確認した状態です。公開者の記述自体が正しいことを独立検証した状態ではありません。配列ハッシュだけで意味が正しいと認定することもありません。

略語辞書による候補や信頼度スコアだけでは昇格しません。明示JSON定義表に加え、PhysioNet HTMLの限定した測定手順記述を、節・適用範囲・原文位置付きで変換するアダプターを追加しました。JSONはharmo用の入力仕様であり、PhysioNetがこの形式を提供しているという意味ではありません。PDF・任意の表・一般的な自由文解釈は未対応です。

## HTMLの適用範囲付き抽出

HTMLを見出しと段落に分解し、Methods/Data Descriptionだけを昇格対象にします。データセット版付きURLと対象記録を照合し、原HTMLのSHA-256、見出し、正規化段落内の文字位置、原文、適用範囲の根拠、規則版を保存します。今回の規則は調査対象資料を見て作成した限定的な英語テンプレートであり、汎用的な自然言語理解や独立評価済み抽出器ではありません。

- 「各被験者の前脛骨筋へ針電極を挿入」という明示文と対象記録の単一EMGチャンネルを照合し、筋と電極を付与。複数チャンネルなら割り当てません。左右は推定しません。
- 同じ段落に抵抗下背屈とその後の弛緩がある場合、記録の測定手順として保持。全サンプルが収縮中というラベルやイベント時刻は生成しません。
- 「データセットは歩行信号」「被験者ごとにWFDBファイルを提供」というData Descriptionの明示文を適用範囲の根拠とし、Methodsの歩行手順・sEMG取得文・略語展開を接続します。直線と旋回が混在することを保持し、定常直進だけの信号とは扱いません。
- 明示EMG単位はヘッダーと照合し、不一致なら単位だけ保留します。
- 指定した否定・不確実性・例外表現を含む段落を昇格しません。一般的な否定や照応を網羅しているわけではなく、未対応文は新たな検証を要します。

保存済み実データではemgdbの2記録で各3属性、semgのS01で11属性、S10で21属性をsource_verifiedとして保持できました。S01の単位10件はconflictingです。科学的用途の信頼レポートは引き続き未評価のままです。

## 明示的な入力例

取得ファイル名が `*.record-definitions.json` のものを検出します。全フィールドを厳密に照合し、ワイルドカードや記録順による割当ては使いません。以下のハッシュ欄は実際の対象ヘッダーのSHA-256に置換する必要があります。

```json
{
  "format": "harmo-record-definitions/1.0",
  "dataset": "example/1.0.0",
  "definitions": [
    {
      "record": "S01.hea",
      "header_sha256": "REPLACE_WITH_ACTUAL_HEADER_SHA256",
      "channel": "semg LT TIB.A",
      "field": "side",
      "value": "left"
    }
  ]
}
```

対応属性は `anatomy`、`side`、`sensor_type`、`unit`、`task`。anatomyはentity_type・canonical_label・ontology_term、taskはactivity・ontology_terms・facets・compatibility_groupを必要とします。語彙の名前・版・識別子は明示入力とし、似た筋名からオントロジー対応を推定しません。taskは記録単位であるためchannelは空文字とします。

## 規則と出力

1. データセット版、記録名、ヘッダーハッシュ、チャンネル名を照合。
2. 適用可能なすべての定義を属性ごとに集約。一意なら型・契約検証へ進み、相違があればconflicting。
3. ヘッダー単位と資料の不一致はunit属性の矛盾にする。別の属性の昇格を止めない。
4. 筋群はmuscle-groupとして保持し、単一筋へ展開しない。既存比較規則はこれを単一筋比較として許可しない。
5. 承認した属性に定義ファイルのURL・SHA-256・JSON Pointer・規則版を付ける。
6. `recording.semantic.bundle.json` と `semantic.promotion.json` を新規作成。原bundleと波形を変更しない。既存の意味対応済みbundleへの上書き昇格は拒否し、原bundleから再評価する。

定義ファイルが不正であれば、そこに矛盾する定義がある可能性を除けないため、その実行では昇格しません。新しい意味情報の表示は既存のペア比較・出力経路から読み取られますが、信頼レポートや科学的利用判定は自動でpassにしません。単一チャンネルの部分的な昇格を記録全体の承認へ拡大しません。

## 検証範囲

合成の明示定義表とHTML規則で、昇格成功、版・ハッシュ不一致、矛盾の属性別隔離、筋群、誤った型、記録違い、見出し違い、否定、複数チャンネルへの過剰適用、既存結果の保護をテストしています。HTML接続前のJSONのみの実証ではsemgの昇格は0件でした。上記のHTML実証と区別します。これは未知資料に対する抽出性能評価ではありません。
