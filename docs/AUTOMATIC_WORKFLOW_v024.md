# Figshare・Mendeleyを含む一括処理 v024

## 対応する入口

`harmo harmonize-batch` は、版を固定したPhysioNet・Figshare・Mendeley Dataと、Zenodoのrecord URLを共通の処理へ接続する。リポジトリ対応と、すべての記録の解釈・比較が可能であることは異なる。

```json
[
  {"url": "https://doi.org/10.6084/m9.figshare.9784964.v1"},
  {"url": "https://data.mendeley.com/datasets/d4y7fm3g79/1"}
]
```

```sh
harmo harmonize-batch --jobs jobs.json --output work \
  --max-records 2 --max-bytes-per-url 33554432 \
  --r-library /absolute/path/to/R/library
```

Mendeleyでは `https://doi.org/10.17632/d4y7fm3g79.1` も同じ公開版を指す。未固定の最新版URL、認証が必要なデータ、Figshare collectionはこのコマンドの入口には含めない。既存のcollection取得機能は別の `mixed-batch` に残る。

## 自動で行うこと

1. 公開版のメタデータを保存し、選択ファイルのID・サイズ・チェックサムを固定する。
2. 上限内のファイルを取得して照合する。Mendeleyは公開サイトのsnapshot／folder／file情報とSHA-256、Figshareは既存のPhysioIO接続と公開チェックサムを利用する。
3. 対応形式の読み取り候補を生成し、数値・時刻を検査して共通記録へ保存する。元バイト列も残す。
4. リポジトリ記述・対応文書の根拠を記録へ結び付け、属性確認票を作る。CSV／MATでは実際の読み取りスキーマを示し、架空のヘッダーを作らない。
5. 下肢EMG・側・歩行課題・同側の離散フットスイッチ等の条件を満たす記録だけを、既存の処理計画・周期曲線・診断的比較へ渡す。

名称だけで結び付けるのは、公開ファイル一覧中で元ファイル名が一意で、かつそのファイルから変換されたストリームも一つの場合に限定する。同名ファイルの片方だけを取得しても一意とみなさない。ZIP内は一意なメンバーパスを使う。複数のMAT配列へファイル全体の筋名・課題を一律に継承しない。

## 現在の上限と保留

- Mendeleyのメタデータ列挙は最大100フォルダ・1,000ファイル。ファイル本体は選択分のみ取得するが、現時点ではこの範囲のメタデータ一覧を先に取得する。
- 非PhysioNetの `--max-records` は、取得段階ではファイル／ZIPの個数、後段では処理対象記録数を制限する。MAT／ZIP内部の個別記録をサーバーから部分取得する機能ではなく、変換時のストリーム総数をこの値で制限するものでもない。
- ZIPは既存の安全な1層展開を使う。RAR・7z・tar・gzipはこの入口では取得前に保留する。ZIP内のサイズ・件数制限も適用する。
- 説明資料のJSON・HTML・XML・記録メタデータ表を解釈する。任意のPDF／DOCX／XLSXを自動的に完全読解する機能ではない。
- 電極番号から筋名、裸のtimestampから時刻単位、研究名から全記録の歩行課題を推定しない。未解決属性と未対応構造を理由付きで残す。
- 歩行の数値処理は現在の離散フットスイッチ経路に限定される。任意のIMU・映像・力板からのイベント生成は別途必要であり、この変更には含めない。

## 人が行う作業

筋・左右・課題等の不足は、生成された `semantic-review/packet.json` の原文と対象範囲を確認し、別コピーのdecisionsへconfirm／hold／rejectと実担当者名を記入する。処理履歴・電気状態と生理イベントの対応は `event-review.template.json` で確認する。記録変換自体が保留された場合は、先にその時刻・配列・ファイル形式の条件を解決する必要がある。

確認結果の反映、任意のローカルLLM候補生成、再開と出力の読み方は [v023](AUTOMATIC_WORKFLOW_v023.md) を参照。LLMを指定しない実行はルールベースであり、モデルによる改善を測った実験とは区別する。曲線が得られても、科学的比較や振幅プーリングを自動承認しない。
