# PhysioNetからの一括取得・変換・蓄積（接続実装 v0.1）

既存のPhysioIOを使うURLバッチ経路です。信号の読み取りを独自の新手法として提供するものではありません。

## 現在の対象

- 公開されているPhysioNetの版付きデータセットURL。URLを配列にしたJSONを渡します。
- WFDBの単一セグメント・単一ファイル・単一形式（16/61/80/212/24/32）。他形式のファイルも保存しますが、未接続形式は明記し、全処理完了とは表示しません。
- 原信号・ヘッダー・同一データセット内の関連ファイル、説明ページを取得します。認証が必要なデータ、外部の関連論文全文、Figshare等はこの経路にはまだ接続していません。

## 必要な環境

Python側は既存のharmoに加え `wfdb>=4,<5`。R側は `readWFDB` を公開するPhysioIOと対応するPhysioCoreが必要です。接続確認ではPhysioIO 0.2.4／PhysioCore 0.4.0を一時ライブラリで使用しました。既存のR環境は上書きしていません。

```json
[
  "https://physionet.org/content/emgdb/1.0.0/",
  "https://physionet.org/content/semg/1.0.1/"
]
```

```bash
harmo public-batch --urls urls.json --output local_catalog \
  --r-library /path/to/isolated/R/library
```

初期確認では `--max-records 2 --max-bytes 134217728` を追加できます。件数制限を使った出力は対象データ全体の処理完了ではなく `partial` と表示します。既定では各URLの全ファイルを取得対象とし、全バッチの通信量を1 GiBに制限します。大規模データでは `--max-bytes` を明示して変更してください。

## 実行内容

1. URLからデータセットと版を確定し、一覧と説明ページを取得。
2. 各ファイルを取得してハッシュ保存。SHA256SUMSが提供されていれば原信号・ヘッダーを照合。
3. ヘッダーの時間・単位・ゲインが明示されていること、対応形式・形状・ファイル範囲を検査。
4. PhysioIOで読み取り、別のWFDBリーダーの整数値と明示校正値で全値を照合。WFDBの欠測コードをNaNに対応させ、その操作を記録。
5. 時間、全チャンネル（EMG以外も含む）、単位、原ファイルとの対応を保持して保存。
6. 同名EMGチャンネルを持つ既存記録を候補として、既存の用途別規則でタイミング・振幅を別々に評価。同名というだけで筋の同一性は認定しない。
7. 原データ、変換済み記録、保留理由、判定をSQLiteカタログと実行別ディレクトリに蓄積。

`catalog.sqlite` は記録・ファイル・用途別状態・比較結果・実行履歴を照会するためのローカル台帳です。実配列は各実行ディレクトリの `normalized.npz` に保存します。これは共通の台帳への統合であり、異なる研究の波形を平均・結合して解析してよいという意味ではありません。

`completed` は対象範囲の取得・変換処理についての状態です。科学的用途が支持されたという意味ではありません。説明ページの限定的な規則抽出を追加しましたが、筋・左右・課題・処理状態を各記録に根拠付きで確定する機能は未完成のため、用途判定は原則として `unassessed` になります。比較候補には既存ポリシーが具体的な未解決事項を返します。

## 説明資料の一次スクリーニング（0.2.0）

説明HTMLの段落から、電極種別、限定した課題表現、同期の記載、EMGの明示単位を規則で抽出します。`source.evidence.json` にURL、原資料のSHA-256、段落番号、正規化した段落内の文字位置、全文を保存します。抽出値はすべて候補です。否定・引用・研究内の適用範囲は未解決で、候補を確認済みの記録属性に昇格させません。

各記録の `source.screen.json` は、説明の単位候補とEMG名を持つチャンネルのヘッダー単位を照合し、不一致候補をタイミング・振幅の保留理由へ接続します。単位の表記揺れを照合時のみ統一し、信号値や原ヘッダーは変更しません。SQLiteの `source_screens` に実行別の結果を保存します。これは既存のペア比較とは別の前提条件スクリーニングです。

「限定規則で検索したが該当なし」「関連論文は未調査」「解剖学情報の抽出は未実装」を区別します。検索不一致を情報の不存在と解釈しません。EMGを含まないチャンネル名の信号種別判定、関連論文取得、記録への意味対応、科学的比較の承認はこの機能の対象外です。

保存済み資料は再ダウンロードせず、別ディレクトリへ再評価できます。

```bash
python -m harmo.source_evidence /path/to/run/semg/1.0.1 /path/to/new-screen
```

出力先が存在する場合は停止し、既存結果を上書きしません。このオフライン操作は元のカタログを更新しません。

### チャンネル対応候補（source-screen 0.2.0）

`channel_mappings` に、チャンネル名と資料中の解剖学用語の対応候補を保存します。現在の語彙は tibialis anterior、gastrocnemius lateralis、rectus femoris、vastus lateralis、hamstrings の5語です。全文名または明示した略語トークンを照合し、LT/RT/LEFT/RIGHTから左右候補を取得します。略語規則はコードで版管理し、データセット名やチャンネル順には依存しません。

各候補には資料の該当箇所、元ヘッダー等のハッシュ、適用した規則、未確認理由を保持します。HAMは筋群のまま保持し、単一筋へ展開しません。複数筋・左右の競合、該当語なし、資料内に裏付け候補なしを分離します。測定条件はデータセット水準の候補として添付するだけで、各記録に確定適用しません。一般的な略語でも資料での定義と適用範囲が独立に確認されていないため、既存bundleの解剖学属性や科学的利用判定を承認へ更新しません。

## 用途別の再判定と出力

`public-export` はカタログを読み取り専用で開き、指定した基準記録・チャンネルに対してEMG候補を既存ポリシーで再判定します。同名だけで対象を限定せず、判定結果の保存値も再利用しません。例:

```json
{
  "reference": {"dataset":"semg/1.0.1", "name":"S10.hea", "channel":"semg LT TIB.A"},
  "purposes": ["activation-timing", "amplitude-pooling"]
}
```

```bash
harmo public-export --catalog local_catalog/catalog.sqlite --request request.json --output new_selection
```

取得と同時に最後まで実行する場合は `public-batch` に `--selection-request request.json` を付けます。結果は当該実行の `selection/` に保存されます。基準記録は取得後のカタログ内で一意に解決できる必要があります。

課題・解剖学を扱う1.2.0契約、無条件の比較可能判定、全信頼次元のpass、資料スクリーニングの不一致候補なし、配列ハッシュ・形状・時間軸・有限値の検査をすべて満たす場合のみ、基準・対象チャンネルを別配列としてNPZに出力します。条件付きの場合は変換が未実行なので保留します。信頼・意味属性は入力契約に依存し、科学的な正しさをこのコマンドだけで独立検証するものではありません。

`selection.report.json` に用途、判定規則と理由、保留または出力状態を保存します。出力には入力・出力ハッシュと単位が付属します。複数記録を平均したり一つの時間軸に連結したりしません。同じ研究・記録に複数版がある場合は曖昧な基準を選ばず停止します。対象が0件でも報告書を出し、終了値2を返します。既存出力先は上書きしません。

## 残る制約

明示的な記録定義JSONが含まれる場合の属性単位昇格を追加しました。[仕様と限界](SEMANTIC_PROMOTION.md)を参照してください。元資料からの自由文解釈の自動化や、科学的利用の承認とは別です。

Figshare/Mendeley/Zenodo、他のPhysioIO形式への自動振り分け、資料本文・関連論文の情報抽出、動作解析の自動実行、失敗ファイルだけを再取得する再開、広範な独立評価は未完了です。再実行は別の実行ディレクトリを作成し、カタログの同じ原信号版は重複登録しませんが、現在は再ダウンロード・再変換します。

本機能の接続テストは、PhysioIOのリーダーや各解析パッケージの新規性・包括的な性能評価に置き換わりません。[論文化の責任分界](../paper/revision_plans/physio_package_publication_boundary_v001_2026.09.13-r1.md) に従います。
