# 確認画面とハーモナイズ処理の接続 v003

## 操作

生成済みの確認データを指定し、ローカル実行サーバーを起動する。出力には存在しないフォルダを指定する。

```sh
PYTHONPATH=src python -m harmo.semantic_server \
  --workspace paper/results/semantic_workspace_v006_2026.09.15-r6/workspace.json \
  --output /absolute/path/to/new-session
```

表示された `http://127.0.0.1:…/#…` を同じPCのブラウザで開く。このURLにはセッション用の認証情報が含まれるため共有しない。サーバーの終了は起動した端末でCtrl+C。静的なreview.htmlは引き続き確認・JSON保存用であり、それだけでは処理を実行できない。

1. 筋・左右・課題について候補と資料を照合し、確認・修正・保留する。
2. 「確認を反映して再評価」を押す。確認・保留済みの判断だけを固定して保存し、根拠と適用範囲の既存検査へ渡す。未入力・未確認を人の確認に見せかけない。確認が0件でも、既存の自動判定だけによる条件確認は可能。
3. 処理可能な記録、確認前後のチャンネル数、使用する処理手順、タイミングと振幅それぞれの判定・保留理由を確認する。再評価の段階では診断波形はまだ作成しない。ただし既存の目的判定で許可されるペア出力があればassessment以下に保存される。
4. 「この条件で診断処理を実行」を押す。保存した計画と入力ハッシュを再検査し、既存の歩行EMG処理を実行する。判断を変更した場合は先に再評価が必要。
5. 波形表CSV、診断データJSON、実行記録、残る課題を画面から保存する。

## 範囲

- 既存の確認票・取得済みカタログを入力とする。URL入力・新規取得のGUIは未接続。
- この接続版の標準上限は2記録、各16チャンネル、256曲線、256比較。取得済みの全記録を処理したとは扱わず、未処理数を表示する。
- 確認画面の表示対象以外の判断は変更させず、既存の確認・保留も保持する。
- 元カタログ・元波形は読み取り専用。意味付けを反映した計画、判定、数値出力はセッション下の新しい実行フォルダに保存する。元カタログへの永続的な書き戻しは行わない。
- イベントの生理学的定義、前処理履歴、同期、正規化、被験者対応などの条件は、筋名の確認から自動で承認しない。イベント確認の追加GUIは未接続。
- 診断曲線と記録間の診断的比較を作成しても、科学的比較や振幅プーリングの承認とはしない。
- LLMの新規推論・精度評価は今回の処理に含まれない。
- 判断の保存ファイルは既存のsemantic_workspaceの--decisionsで再利用できる。サーバー停止後のセッション内実行再開は未実装。新しい出力フォルダで起動し直す。

## 保護と記録

サーバーは127.0.0.1のみにバインドする。APIはセッション認証、Host検査、書き込み時の同一Origin、JSONサイズ上限を必要とする。HTTPから任意のファイルパスやコードを指定して実行できない。資料がローカルに不足している場合は取得せず保留・失敗を報告する。

各実行フォルダには判断、確認受領記録（確認がある場合）、計画、目的判定、数値出力、未解決事項を保存する。失敗途中の出力も上書きしない。ブラウザを閉じても保存済みの出力は残るが、未保存の入力は残らない。

試験内容と実データの範囲は[接続検証報告](../paper/results/semantic_integration_v001_2026.09.15-r1/REPORT_ja_v001.md)を参照。
