# ローカルファイルの自動設定と試験変換

`harmo propose-mapping` は、指定ファイルの構造を調べ、既存形式の設定候補を作成し、全行を読み取って時間・値・欠測・ラベルの保持を検査します。LLM、ネットワーク探索、任意コード生成は使用しません。出力は必ず新しいディレクトリに保存します。

## 入力と実行

### MAT動作系列（automap 1.5）

登録済みStudy 38レイアウトの `Marker/MarkerVarName/KinFreq` と `Grf/GrfVarName/GrfFreq` を追加。
EMG・マーカー・床反力を独立した記録設定として出力し、それぞれの周波数から相対時計を作ります。
ラベルと値を保持しますが、単位・座標系の適格性は未確定です。各系列のTimeStampは保存するだけで
異種系列の同期や時間原点補正はしません。

Ang/Mom/Pwr/Comは時間軸の意味に根拠がないため、KinFreqを流用せず保留します。101列などの
配列長だけで歩行周期正規化と断定もしません。単一点の静止データも時系列としては採用しません。
安全上限はファイル32 MiB、各信号種別200万セル（EMG/Marker/Grf合計最大600万セル）です。
系列を追加しても、マーカーの大きさがEMGの割当を使い切らないよう種別ごとに制限します。

### TRC／MOT／STO（automap 1.4）

TRCはマーカー名、XYZ列、宣言行数、フレーム番号、Time、DataRateを照合します。
時間とフレーム時計の許容差は1フレームの0.1%（書き出し丸め用）で、元の時刻は変更しません。
元のフレーム番号もNPZに保存します。余分な値・重複ラベル・周波数矛盾は保留します。

MOT／STOはendheaderと表の形状を確認し、`time_units=s` または `timeunit=s`（msも可）の
明示宣言がある場合のみ採用します。通常のMOTでもこの宣言がなければ現在は保留します。
行数が101、範囲が0–100などの理由で、正規化された軸を秒と推測しません。
信号ごとの角度・力等の意味、単位、座標系はこの処理では確定しません。

生成設定のみ `reader_options.round_trip: true` を指定し、数値字句から得たfloat64値との完全一致を
確認します。既存のOpenSimリーダーの既定動作は維持します。元の時間軸の原点・単位を保持し、
再標本化や正規化をしません。

### C3D（automap 1.3）

`--discover` はC3DのPOINTとANALOGを別の設定・NPZに展開します。周波数は各系列のRATEを読み、
ヘッダーと照合します。単位は元宣言を記録し、欠如・個数不整合時は未確定とします。
時間は各系列の相対時計であり、異なる系列の同期・時間原点補正を主張しません。

POINTでは既存リーダーに合わせて名前空間接頭辞を除くため、元ラベルも保存し、短縮後の重複は保留。
第4成分は補助配列として保存します。座標系、マーカーの解剖学的意味、欠測マスクの解釈は別課題です。
ANALOGは新しい明示モード `analog-native` を使用します。ezc3dによるデコード／スケーリング後の値を
保持し、追加の力学校正・回転・CoP計算を行いません。従来の `analog` の動作は変更していません。

出力は `file-*/record-*/` に保存します。一方の系列が不正なら他方の成功を残し、ファイルをpartialとします。
`accepted` でも対象はPOINT/ANALOGの構造変換のみであり、C3Dの全付随メタ情報の移植ではありません。
読み取りにはezc3dが必要です。

### 複数記録MAT（automap 1.2）

複数要素structを検出した場合、既存Study 38の `EMG` / `EmgVarName` / `EMGFreq` 構造規則で
各記録を展開する処理を追加しました。ファイル名や被験者番号には依存しませんが、この登録済み
レイアウトへの対応であり、未知のMAT構造から周波数の意味を推論するものではありません。
`EMGFreq` をHzと読む規則は既存アダプターから継承します。

各記録の信号と、同一スコープまたは一意な祖先スコープのラベル・周波数から設定を生成します。
局所的な宣言が不完全、複数階層で競合、行列の向きが曖昧な場合は保留します。
筋名ラベルは保持しますが、課題や左右の意味を独立に確認したとは扱いません。

各 `file-*/record-*/` に波形と結果を保存し、`config.json` に記録別のdraft設定を出力します。
時間は周波数から作る相対時計です。元の `TimeStampEmg`、`Task`、`Foot` は文脈情報として保存し、
自動的な時間原点補正や異なる計測系列の同期は行いません。
他の数値配列が未対応ならファイルは `partial`、終了コードは2です。記録別EMGの成功と
ファイル全体の処理完了を区別します。既存の科学的適格性判定や倉庫投入は実行しません。

### フォルダー指定

対象フォルダーだけを指定して、候補抽出から設定生成・全行の試験変換まで実行できます。

```bash
harmo propose-mapping --input-root /path/to/extracted_source \
  --discover --output /path/to/proposal_v002
```

`--discover` と `--manifest` は排他です。探索結果は `discovery.json` に保存します。
拡張子で信号候補・説明資料・要展開アーカイブ・未分類を区別する暫定分類であり、
候補の内容は隔離した読み取り処理で検査します。説明文のTXTは試験時に保留となり得ます。
リンクは辿らず、探索は1万エントリ／候補1000件まで。アーカイブ展開やPDF本文解釈はしません。

追加した自動設定の範囲：

- TXT：CSV/TSVと同じ明示ヘッダー・時間単位条件で区切りを判別。
- MAT：単一要素structを最大6階層まで探索し、信号・ラベル・時間または周波数が同じ階層に
  一意に存在する場合、既存リーダー用のフィールドパスを生成。
- 複数要素struct、セル、複数信号、階層をまたぐメタ情報は保留。最初の記録だけを選ばない。

後述の旧対象外条件のうち「入れ子MAT」は、この単一要素structの範囲のみ対応済みです。
C3Dは1.3、TRC/MOT/STOは上記1.4の条件付き範囲で対応しました。既存設定による変換対応と
自動設定生成の対応範囲は異なります。

`scripts/evaluate_discovery_automap.py` は、設定生成後に元ファイルのハッシュだけを論文の78設定と
照合します。原データ未評価と自動設定保留を区別し、候補生成を数値再現成功とは扱いません。

通常の `pip install -e .` の依存で動作します。Spark、倉庫、OpenSimは不要です。現在の実行対象OSはmacOS/Linuxです。

ファイル台帳をJSONで指定します。パスは入力ルートからの相対パスです。

```json
{
  "files": ["trial.csv", "trial.mat"],
  "metadata": {}
}
```

```bash
harmo propose-mapping --input-root /path/to/source \
  --manifest /path/to/manifest.json --output /path/to/proposal_v001
```

出力は入力ルートの外に置きます。終了コードは全件採用なら0、保留・非対応を含めば2、台帳等のエラーなら1です。保留があっても他のファイルは検査し、結果を保存します。

## 自動で決めるもの

- CSV/TSV：区切り（コンマ・タブ・セミコロン）、ヘッダー、明示時間列、元ラベル、各ファイルのみを対象とする対応設定。
- 標準数値MAT：唯一の信号配列、明示された文字列ラベル、ラベル数で一意に決まる配列の向き、明示時間キーまたは正の周波数。
- 入力ハッシュ、設定の検査結果、隔離した変換結果、各保留の理由。

CSVの時間は `time_s`, `time_seconds`, `time_ms`, `time [s]`, `time [ms]`（大文字小文字は不問）。MATは同じ時間キー、または `fs_hz` / `sampling_rate_hz`、ラベルは `labels` / `channel_names` を受け付けます。時間が複数、複数の信号配列、正方配列で向きが曖昧、といった場合は推測採用しません。

`time` のように単位がない場合は、根拠付きで補完できます。補完前の記録は消さず、別の出力先で再実行します。

```json
{
  "files": ["trial.csv"],
  "metadata": {
    "trial.csv": {
      "time_unit": "s",
      "source_reference": "確認した資料のパス・版・該当箇所"
    }
  }
}
```

CSVに限り `time_column` も指定できます。資料そのものを自動読解・真偽検証する機能ではありません。元ヘッダーと補完単位が競合すれば保留します。

## 出力と採用の意味

| 出力 | 内容 |
|---|---|
| `config.json` | 既存設定形式の候補。必ず `dataset_status: draft` |
| `report.json` | ファイル別status、ハッシュ、構造、根拠、未解決属性、確認事項、集計 |
| `file-*/converted.npz` | 採用ファイルの time と values（行×チャンネル）。ラベルと単位は隣接するresult.jsonに保存 |
| `file-*/request.json`, `result.json` | 隔離試行の入力・出力。絶対パスと指定メタ情報を含むため共有前に確認 |

`accepted` は**この入力版に対する構造変換の検査済み**という意味です。実際の倉庫投入、被験者統合、科学的用途の適格性、ライセンスの確認ではありません。倉庫投入は一切せず、通常の取り込み経路もdraft設定を拒否します。`active`への変更だけで完成した研究設定になるわけではありません。確認済みの定義・ID・用途別根拠が別途必要です。

時間は元の単位のまま保持し、`static_metadata.time_unit` と報告書に記録します。msを自動的に秒へ変換しません。CSVの数値読込は `float_precision: round_trip` を明示し、字句から得たfloat64値との一致を許容差ゼロで検査します。MATのラベルは明示設定 `strip_channel_names: true` で周囲の空白を除き、変更前ラベルも保存します。既存研究の既定の読み取り動作は変えません。

チャンネルは数値変数として保持するだけで、すべてEMGと推測しません。CH1やTAから筋名・左右を補いません。現行の完全一致規則は Right/Left と正式名 Tibialis Anterior / Medial Gastrocnemius / Soleus、および任意の [V]/[mV]/[uV] に限定されます。これは元ラベルに書かれた内容の転記であり、独立した同定ではありません。センサー、処理状態、課題、被験者、公開許可は自動確定しません。

## 限界・保留

- 入れ子・セル・オブジェクト・MCOS MAT、HDF5 MAT、複数周波数、アーカイブ、ヘッダーなし表、複数信号候補は対象外または要確認。
- 時間欠如・単位競合・不正時間・重複列・既知のID列・長形式・欠損行の黙示除去・無限大・整数精度喪失は採用しない。NaNの信号値・全欠測行は保持する。
- 既知のID名以外の数値列の意味までは自動検証しない。構造採用を意味同定と混同しない。
- 上限は1000ファイル、1ファイル32 MiB、200万セル、1ファイル30秒（CPU25秒）。Linuxはアドレス空間4 GiB上限。macOSはメモリ上限を強制できないため、サイズ・セル・時間制限のみ。悪意ある入力に対するセキュリティサンドボックスではない。
- 探索するルートは対象データに限定する。アーカイブ展開、外部パス参照、プラグイン実行、既存出力の上書きはしない。

```bash
python -m pytest -q tests/test_automap.py
python scripts/evaluate_automap.py --output /path/to/new_evaluation_v001
```
